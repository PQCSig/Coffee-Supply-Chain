### Exploitation evidence (redacted)

No live-fire exploitation was performed (contracts not deployed to any live network since Rinkeby's 2022 shutdown; the Rinkeby deployment is defunct). Findings FT-1/FT-2/FT-3 are analytic proofs from the Solidity control flow; each is pinned by a regression test that fails against the pre-fix contract.

### Honest downgrades

- `checkValue` refund uses `transfer()` inside a modifier (2300-gas stipend) — reentrancy is theoretically mitigated; recorded as accepted pattern for 0.5.x, revisit on any compiler upgrade.
- `receiveItem`/`purchaseItem` accept *any* retailer/consumer rather than a specific one — accepted demo-level design, documented here with reasoning; tighten if ever used with real value.
- Vendored `src/js/truffle-contract.js` (258 KB, 2018) is unauditable legacy code — flagged for replacement with the npm-published `@truffle/contract`, not replaced this cycle (UI rewrite is out of scope for gap-closure).
- Standalone role contracts deployed by `migrations/2_deploy_contracts.js` are dead code — `SupplyChain` inherits its own role registries; the deployed duplicates are unused. Left in place for migration compatibility; candidate for removal on toolchain migration.

## Scope deltas & feed forward

New surface this cycle: CI gate, dependabot, solhint linting. Feed-forward items for the Build Queue:

1. **Never reuse the exposed Infura project ID** (FT-5, closed) — login is unrecoverable, so the ID in public history is permanently public; **redeploy precondition**: create a fresh Infura account/project and set the new `INFURA_PROJECT_ID` before any future deployment.
2. **Toolchain migration** — Truffle is EOL (sunset Q4 2023); migrate to Foundry or Hardhat, replace vendored `truffle-contract.js` with ethers.js or `@truffle/contract`, and reassess solc 0.5.16 → current. The DApp UI's `web3` dependency is **archived upstream** (ChainSafe sunset 2025-01; EF archive 2025-03) — target **viem or ethers.js** for the rewrite; this also dissolves the FT-12 exception ledger. `solhint` 6.x bump belongs to the same migration (needs Node ≥ 20; 3.x is adequate for solc 0.5.x). Major-version drift is documented in README "Dependency & update policy" and triaged monthly via `npm outdated` — never blind-bumped.
3. **Port the remaining red-team machinery** — the exception ledger and audit gate are done; still missing: the SSVC/KEV/EPSS triage script, SLA aging report, and a ZAP baseline DAST workflow (`red-team-dast.yml`, valuable once server routes or server-side auth exist). Port them onto this repo's actual surface — or fork the template down to what a non-Next.js DApp needs.
